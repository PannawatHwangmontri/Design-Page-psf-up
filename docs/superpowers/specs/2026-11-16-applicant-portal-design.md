# ระบบบัญชีอาจารย์ผู้ยื่นขอ PSF (demo บนเครื่องเดียว) — Design

วันที่: 2026-11-16 · สถานะ: อนุมัติแล้ว (ผู้ใช้ตอบ "ตกลง")

## เจตนา (Intent)

อาจารย์ที่จะยื่นขอ PSF ต้องมีบัญชีเพื่อดูสถานะการยื่น อัปโหลดหลักฐาน และกรอกแบบฟอร์มยื่นขอได้ในที่เดียว งานนี้เป็น demo สำหรับนำเสนอ ยังไม่ใช่ระบบจริง

## เป้าหมาย (Goals)

- อาจารย์สมัครบัญชีและล็อกอินได้
- หน้าอาจารย์มี 3 ส่วน: สถานะการยื่น, อัปโหลดไฟล์ PDF หลักฐาน, กรอกแบบฟอร์มยื่นขอ
- ข้อความทั้งหมดมีไทยและอังกฤษ แยกไฟล์แปลภาษา

## ไม่ทำ (Non-goals)

- ไม่มีเซิร์ฟเวอร์ ฐานข้อมูล หรือการยืนยันตัวตนจริง
- ไม่มีหน้าให้แอดมินดูใบสมัครของอาจารย์ (ข้อมูลอยู่ในเบราว์เซอร์นี้เท่านั้น)
- ไม่แก้ระบบแอดมินและ `src/lib/site.tsx` เดิม

## ข้อจำกัดที่ยอมรับ (Anti-goals)

- รหัสผ่านเก็บเป็น hash ในเบราว์เซอร์ แต่ยังไม่ปลอดภัยพอสำหรับงานจริง ห้ามใช้รหัสผ่านจริง

## แนวทางที่เลือก (Approaches)

1. **แยกโมดูลใหม่ (เลือก):** `src/lib/applicant.ts` ใช้ localStorage คนละ key คือ `psf-applicants` และ `psf-applicant-session` ไม่กระทบระบบแอดมิน
2. ต่อท้ายระบบแอดมินเดิม: ผสมบัญชีอาจารย์เข้า `psf-data` ผ่าน `saveData` ผลคือแก้ `site.tsx` และเสี่ยงกระทบ `/admin`
3. ใช้ Supabase: ตรงกับความต้องการจริงแต่ผู้ใช้เลือกไม่ทำ

## การออกแบบ (The how)

- **ไฟล์ใหม่:** `src/lib/applicant.ts` มีฟังก์ชัน `register`, `login`, `logout`, `useApplicant`, `saveApplication`, `uploadEvidence`
- **รหัสผ่าน:** hash ด้วย SubtleCrypto (SHA-256) ก่อนเก็บ แม้เป็น demo ก็ไม่เก็บตรง ๆ
- **หน้าใหม่:**
  - `src/app/[lang]/applicant/login/page.tsx` มีทั้งฟอร์มล็อกอินและสมัคร
  - `src/app/[lang]/applicant/page.tsx` หน้าอาจารย์ 3 ส่วน ถ้ายังไม่ล็อกอินให้ redirect ไป login
- **เมนู:** เพิ่มลิงก์ "เข้าสู่ระบบอาจารย์" ใน `src/data/nav.ts` และ `SiteHeader`
- **ข้อความ:** เพิ่มคีย์ `applicant` ใน `src/data/content.ts` (ไทย + อังกฤษ)
- **ไฟล์ PDF:** เก็บเป็น data URL จำกัดขนาดไม่เกิน 2 MB ต่อไฟล์ ถ้า localStorage เต็มให้แสดงข้อความแจ้ง
- **สถานะการยื่น:** ค่าเริ่มต้น "ยังไม่ยื่น" เมื่อบันทึกแบบฟอร์มแล้วเปลี่ยนเป็น "รอตรวจ"
- **Hydration:** ใช้รูปแบบเดียวกับ `useSite` คือ state + effect เพื่อให้ HTML ฝั่ง server ตรงกับ client ตอนแรก

## การตัดสินใจที่ผมเลือกเอง (ตรวจได้)

- การสมัครให้อาจารย์สมัครเองในเบราว์เซอร์นี้
- มีสถานะ 4 ค่า: ยังไม่ยื่น, รอตรวจ, ผ่านรอบแรก, ไม่ผ่าน (แอดมินเปลี่ยนสถานะไม่ได้ในเวอร์ชันนี้)
- ฟอร์มมี 4 ช่อง: ชื่อ-นามสกุล (mock), คณะ, ตำแหน่ง, ระดับที่ขอยื่น

## สิ่งที่เหลือให้ผู้สร้าง (ตรวจในแผน)

- ตัวเลือกระดับที่ขอยื่น ใช้ค่าเดียวกับระดับใน `src/data/content.ts` หรือไม่
- ตำแหน่งลิงก์เมนูในมือถือ
